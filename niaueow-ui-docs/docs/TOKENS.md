# Design Tokens

Figma Variables are the single source of truth for colors, typography, radius, spacing and shadows. A Node script turns the Figma export into CSS. Nobody edits the CSS by hand.

## Figma structure

| Collection | Modes | Example variables | Used by components? |
|---|---|---|---|
| Primitives | one | `color/blue/600`, `color/gray/100` | No, only referenced by semantic variables |
| Semantic | Light, Dark | `color/primary` → `{color/blue/600}` in Light, `{color/blue/400}` in Dark | Yes |

Components use semantic tokens only. Rebranding means pointing semantic tokens at different primitives.

## Pipeline

```
Figma Variables
  └─ export plugin ──► packages/ui/tokens/figma/<export>.json
                          └─ pnpm tokens (scripts/build-tokens.ts)
                                ├─ validate shape (zod)
                                ├─ resolve aliases per mode
                                ├─ validate values
                                └─ write src/styles/tokens.css
                          └─ pnpm tokens:contrast (scripts/check-contrast.ts)
```

### What `pnpm tokens` does

1. **Validates the file shape** against a zod schema. Unknown shapes fail with a clear message.
2. **Resolves aliases** for each mode. Missing references and alias cycles fail and print the variable path.
3. **Validates values.** Colors must parse with culori. Dimensions must use known units. Font family strings may not contain `;`, `{`, `}` or `<`. Anything else is rejected, so a malformed export cannot inject CSS.
4. **Writes `src/styles/tokens.css`** deterministically (sorted keys, stable formatting) with a `GENERATED ... DO NOT EDIT` header.

CI regenerates the file and fails if it differs from the committed version.

### What `pnpm tokens:contrast` does

Checks each foreground/background pair in both modes against WCAG 2.2:

| Pair type | Minimum ratio |
|---|---|
| Text on background | 4.5:1 |
| UI borders, focus rings, icons | 3:1 |

The pair list lives in `packages/ui/scripts/contrast-pairs.ts` (for example `primary-foreground` on `primary`, `foreground` on `background`, `muted-foreground` on `muted`). A failing pair fails CI and needs a design decision in Figma.

## Naming rules

| Figma variable | CSS variable | Tailwind theme key | Utility example |
|---|---|---|---|
| `color/blue/600` (primitive) | `--n-blue-600` | none | none |
| `color/primary` | `--n-primary` | `--color-primary` | `bg-primary` |
| `color/primary-foreground` | `--n-primary-foreground` | `--color-primary-foreground` | `text-primary-foreground` |
| `radius/md` | `--n-radius-md` | `--radius-md` | `rounded-md` |
| `font/sans` | `--n-font-sans` | `--font-sans` | `font-sans` |
| `shadow/sm` | `--n-shadow-sm` | `--shadow-sm` | `shadow-sm` |
| `spacing/base` | `--n-spacing` | `--spacing` | `p-4` (multiples of base) |

Rules:
- Figma path segments become kebab-case joined with `-`.
- The `color/` prefix is dropped for color tokens.
- Primitives get CSS variables but no Tailwind utilities, so the consumer's own Tailwind palette stays untouched.
- The final mapping for the actual Figma file is recorded in `docs/PLAN.md` after the first export is read.

## Generated output shape

```css
/* GENERATED by scripts/build-tokens.ts. DO NOT EDIT. */
@layer base {
  :root {
    /* primitives */
    --n-blue-400: oklch(0.707 0.165 254.6);
    --n-blue-600: oklch(0.546 0.245 262.9);
    /* semantic: light */
    --n-primary: var(--n-blue-600);
    --n-primary-foreground: var(--n-white);
    --n-radius-md: 0.5rem;
    --n-font-sans: ui-sans-serif, system-ui, sans-serif;
  }

  .dark {
    --n-primary: var(--n-blue-400);
    --n-primary-foreground: var(--n-blue-950);
  }
}
```

Values above are illustrative; real values come from Figma.

## Updating tokens after a Figma change

1. Change variables in Figma (keep the primitives / semantic split).
2. Export with the same plugin and settings.
3. Replace the file in `packages/ui/tokens/figma/`.
4. Run:
   ```bash
   pnpm tokens
   pnpm tokens:contrast
   ```
5. Check the diff of `tokens.css` and look at Storybook's Colors page in both modes.
6. Add a changeset. Renaming or removing a semantic token is a breaking change for consumers who override it.
7. Commit the export file and the generated CSS together.

## Adding a new semantic token

1. Add it to the Semantic collection in Figma with values for Light and Dark.
2. Follow the update steps above.
3. If it is a foreground/background pair, add it to `contrast-pairs.ts`.
4. Document it in the token reference in [THEMING.md](./THEMING.md).
