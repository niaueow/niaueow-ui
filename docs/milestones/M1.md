### Details worth knowing

- **ESLint:** `js.configs.recommended`, `typescript-eslint` recommended, `eslint-plugin-vue` `flat/recommended`, `eslint-config-prettier/flat` last. Errors on `vue/no-v-html`, `no-eval`, `no-implied-eval`, `no-new-func` (also catches `Function(...)` without `new`). Browser globals for `packages/*/src` (needed for `no-implied-eval` to see `setTimeout("...")`), Node globals for scripts. Each rule was checked against a sample file.
- **Prettier:** `semi: false`, `singleQuote: true`, `printWidth: 100`. Markdown is ignored (see deviations).
- **Build:** `vite build` (ESM, `preserveModules`, every dependency and peer external by name and subpath) then `vue-tsc -p tsconfig.build.json` then `copy-assets.mjs` (`index.css` to `dist/styles.css` unprocessed; root `README.md` and `LICENSE` into the package, gitignored).
- **Tests:** Vitest with jsdom and `@vue/test-utils`, v8 coverage. Threshold `src/components/**`: 80% lines and branches. Verified with a temporary under-tested component: the run fails with `Coverage for lines (20%) does not meet "src/components/**" threshold (80%)`. With no components it passes.
- **verify:** runs lint, typecheck, test, build, check:package, `pnpm audit --prod --audit-level=high` in order and stops at the first failure (checked from PowerShell with a planted `eval`).
- **CI:** `ubuntu-latest` runs every check. `windows-latest` (x64) and `windows-11-arm` run install, build, test.
- **Release:** Changesets sub-actions in four jobs. `select-mode` decides. `version` (`contents`, `pull-requests: write`) opens the Version Packages PR; it pushes through the GitHub API so checkout keeps `persist-credentials: false`. `pack` runs `pnpm verify` and packs the tarball. `publish` (`contents: write`, `id-token: write`) publishes it through trusted publishing. No `NPM_TOKEN`. Release jobs set `package-manager-cache: false` to avoid cache poisoning.
- **Claude Code:** deny `Read(.env*)`, `Read(~/.npmrc)`; publishing in any position (`npm|pnpm * publish`, `* changeset publish`), npm account and release commands, `npm token`, `git push` in any position; shells as pipe targets (`sh`, `bash`, `zsh`, `sudo`, `powershell`, `pwsh`, `iex`). Each Bash rule has a `PowerShell(...)` twin. The `PostToolUse` hook formats edited files inside the repo with Prettier's Node API, using only the root config, and always exits 0. Hardened after the security review (below).

## Deviations from the docs and the M1 brief

1. **TypeScript 6.0, not the latest (7.0).** typescript-eslint 8.72.2 requires `typescript <6.1.0`. Noted in `TECHSTACK.md`.
2. **`.d.ts` via vue-tsc, not vite-plugin-dts.** One fewer dependency; `TECHSTACK.md` updated.
3. **Relative imports use `.js` extensions** (`from './plugin.js'`). Without them the emitted `.d.ts` fails Node ESM resolution and attw reports "Internal resolution error". Added to `COMPONENT-GUIDELINES.md`; `ADDING-A-COMPONENT.md` example updated. The M5 generator must follow it.
4. **attw excludes `./styles.css`** (`--exclude-entrypoints ./styles.css`). attw looks for types behind every export and a stylesheet has none.
5. **`pnpm verify` runs in the release `pack` job, not the `publish` job.** This is the Changesets trusted-publishing layout; it keeps `id-token: write` on a job that runs no project build.
6. **Markdown is excluded from Prettier.** The hook reformatted whole docs (table alignment, quotes inside code blocks) on the first edit. I reverted that and added `*.md` to `.prettierignore`, so docs keep their hand-written style and `pnpm format` does not touch them.
7. **`changesets init` written by hand.** It is interactive in v3. `.changeset/config.json` uses the v3 defaults plus `access: public` and changelog-github; `.changeset/README.md` is the stock file.
8. **README.md and LICENSE are copied at build time** into `packages/ui` (your choice), so `pnpm pack` must run after `pnpm build`.
9. **Docs fixes:** README clone URL `<<GITHUB_USERNAME>>` is now `niaueow`. `CONTRIBUTING.md` prerequisites now say to use native arm64 Node and how to install pnpm (see below).

## Local setup issue found and fixed

Your machine ran x64 Node 22 under emulation. After you installed native arm64 Node 26, `pnpm -v` failed in PowerShell. Cause: global pnpm 11.9 switched itself to the pinned 12.20.0 without running pnpm's install script, so the native binary was never placed (pnpm bug [#16594](https://github.com/pnpm/pnpm/issues/16594), fixed in 11.28.4). Fix applied: `npm install -g pnpm@12.20.0 --allow-scripts=pnpm` (I read pnpm's `install.js` first: it links the bundled `@pnpm/exe.win32-arm64` binary and regenerates npm shims). The old pnpm 11.9 shim in `%APPDATA%\npm` is still on PATH behind `C:\nvm4w\nodejs`; you can delete it with `npm uninstall -g pnpm` under the old prefix or leave it. When you bump `packageManager`, reinstall pnpm the same way. Documented in `CONTRIBUTING.md`.

## Known limitations

- **Claude Code deny rules are best-effort.** They match the command text Claude writes, not the program. `/usr/bin/git push`, `sh -c '...'` or `cat .env` are not caught. The documented hard boundary is Claude Code's sandbox; not configured here.
- **Dependabot vs minimum release age.** Without a Dependabot cooldown (you chose not to add it), a PR that bumps to a version under 3 days old fails `pnpm install --frozen-lockfile`. Re-run CI once the version is 3 days old.
- **`windows-11-arm` runner** is a GitHub-hosted ARM runner for public repositories. If the repo is private, that job will not start.
- The package README on npm is the repo README. Its relative links (`./docs/THEMING.md`) will not resolve on npmjs.com.
